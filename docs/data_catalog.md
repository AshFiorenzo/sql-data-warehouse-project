# Data Catalog — Gold Layer
The Gold Layer is the business-level data representation, structured to support analytical and reporting use cases. It consists of dimension tables and fact tables for specific business metrics.

**Database:** `datawarehouse`  
**Schema:** `gold`  
**Architecture:** Star Schema  
**Database Engine:** DuckDB  
**Objects:** 2 Dimension Views, 1 Fact View

## 1. `gold.dim_customers`

**Description:** Stores consolidated customer information from CRM and ERP systems, including personal details, demographics, and geographical information. 

**Source Tables:** `silver.crm_cust_info`, `silver.erp_CUST_AZ12`, `silver.erp_LOC_A101`

| Column Name | Data Type | Key | Description |
|---|---|---|---|
| customer_key | BIGINT | PK* | Unique surrogate key generated for each customer |
| customer_id | INTEGER | | Original customer ID from CRM |
| customer_number | VARCHAR | | Business identifier for the customer |
| first_name | VARCHAR | | Customer's first name |
| last_name | VARCHAR | | Customer's last name |
| country | VARCHAR | | Customer's country of residence |
| martial_status | VARCHAR | | Customer's marital status (Single, Married, n/a) |
| gender | VARCHAR | | Customer's gender, prioritized from CRM and supplemented by ERP |
| birthday | DATE | | Customer's date of birth |
| created_date | DATE | | Date the customer record was created in CRM |

## 2. `gold.dim_products`

**Description:** Stores current product information, including product identification, categories, pricing costs, and classification. Historical product records are excluded.

**Source Tables:** `silver.crm_prd_info`, `silver.erp_PX_CAT_G1V2`

| Column Name | Data Type | Key | Description |
|---|---|---|---|
| product_key | BIGINT | PK* | Unique surrogate key generated for each product |
| product_id | INTEGER | | Original product ID from CRM |
| product_number | VARCHAR | | Business identifier for the product |
| product_name | VARCHAR | | Name of the product |
| category_id | VARCHAR | | Identifier of the product category |
| category | VARCHAR | | Main product category |
| sub_category | VARCHAR | | Product subcategory |
| maintenance | VARCHAR | | Product maintenance classification |
| product_cost | INTEGER | | Cost of the product |
| product_line | VARCHAR | | Product line classification |
| start_line | DATE | | Date the current product record became effective |

**Business Rule:** Only current products are included (`prd_end_dt IS NULL`).

## 3. `gold.fact_sales`

**Description:** Stores sales transactions, including order information, associated customers and products, transaction dates, quantities, and financial metrics.

**Source Tables:** `silver.crm_sales_details`, `gold.dim_products`, `gold.dim_customers`

| Column Name | Data Type | Key | Description |
|---|---|---|---|
| order_number | VARCHAR | | Unique order reference number |
| product_key | BIGINT | FK* | References `gold.dim_products.product_key` |
| customer_key | BIGINT | FK* | References `gold.dim_customers.customer_key` |
| order_date | DATE | | Date the order was placed |
| shipping_date | DATE | | Date the order was shipped |
| due_date | DATE | | Expected delivery date |
| sales_amount | INTEGER | | Total sales amount |
| quantity | INTEGER | | Number of units sold |
| price | INTEGER | | Selling price per unit |

## 4. Data Relationships

| Parent View | Primary Key | Child View | Foreign Key | Relationship |
|---|---|---|---|---|
| gold.dim_customers | customer_key | gold.fact_sales | customer_key | One-to-Many |
| gold.dim_products | product_key | gold.fact_sales | product_key | One-to-Many |

## 5. Data Integration Rules

| Rule | Description |
|---|---|
| Customer Integration | Combines CRM customer records with ERP demographic and location data |
| Gender Prioritization | Uses CRM gender unless it is `n/a`; otherwise uses ERP gender |
| Product Integration | Combines CRM product information with ERP product categories |
| Historical Filtering | Excludes historical products using `prd_end_dt IS NULL` |
| Surrogate Keys | Generates customer and product keys using `ROW_NUMBER()` |
| Sales Integration | Connects sales transactions to customer and product dimensions using business identifiers |

- **PK/FK labels are logical relationships**, not enforced database constraints, because these objects are views.
- Data types are inferred from your SQL. Verify them against the actual DuckDB schema.
- Your SQL uses `martial_status` instead of `marital_status` and `start_line` instead of `start_date`.
- The source image repeats `country` in the customer dimension, but your SQL correctly includes `created_date` as the final column.
